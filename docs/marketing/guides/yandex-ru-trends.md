## Инструмент 1: Yandex Suggest (основной автономный источник)

### Как получить данные

```
GET https://suggest.yandex.ru/suggest-ff.cgi?part=<URL-encoded запрос>
→ ["prefix", ["подсказка1", "подсказка2", ...]]
```

- User-Agent обязателен (пустой UA иногда режется); пауза 0.3–0.5 с между запросами безопасна.
- ВАЖНО: параметр запроса должен быть URL-encoded — неэнкодированная кириллица возвращает пустой ответ без ошибки.
- Алфавитное расширение: seed + буква («японский язык а», «...б», ...) даёт лонгтейл, которого нет в прямом autocomplete.

### Что смотреть

1. **Кросс-seed частота**: подсказка, выпавшая от ≥2 разных сидов, — подтверждённый спрос-сигнал. Частота 4+ = жирный кластер.
2. **Модификаторы**: «с нуля», «бесплатно», «самостоятельно», «в тг» — профиль рынка. RU-специфика (см. срез ниже): «с нуля» и «бесплатно» сильнее, чем в EN.
3. **Интент-глаголы**: «учить/выучить/начать» — информационный; «в каком приложении» — транзакционный app-интент (наш кейс).

### Срез 2026-10-12 (8 сидов + алфавит 2×18, 271 уникальных, 31 подсказка cross≥2)

Топ cross-seed:
- **«в каком приложении лучше учить японский» ×4** — единственная ×4; прямой app-интент, целевая статья `/ru/blog/best-japanese-learning-app`
- Кластер «с нуля» ×11: «учить японский (язык) с нуля», «...самостоятельно», «...бесплатно», «...в домашних условиях» — подтверждает profile §15 (RU «с нуля» 16% vs EN beginners 2%); целевая `/ru/blog/yaponskiy-s-nulya`
- «бесплатно» ×5 — RU-модификатор ценности; FAQ-статьи уже отвечают
- «тяжело/трудно/сложно ли учить японский» ×3 — болевой интент; целевая `/ru/blog/is-kanji-hard-to-learn`
- «можно ли учить японский в дуолинго» ×2 — конкурентное сравнение; кандидат в `/ru/compare` или блог
- «учить японский по аниме» ×2 — хобби-сегмент; `/ru/blog/learn-japanese-from-anime`
- «японский язык в тг» ×2 — Telegram-интент виден в самом поиске: подтверждение выбора ТГ как RU-канала №1 (SERP-данные: t.me=12)
- «какой японский алфавит надо учить первым», «в каком порядке учить японский» — `/ru/blog/learn-hiragana-katakana`

Полный JSON: агентский артефакт `ru_suggest_2026-10-12.json` (в /tmp/opencode, в репо не ездит — перекачивается скриптом).

## Инструмент 2: Google Trends через pytrends (RU-сегмент)

### Как получить данные

```bash
python3 -m venv venv && ./venv/bin/pip install pytrends "urllib3<2"
# urllib3>=2 ломает pytrends (HTTP 429/401 на payload)
```

```python
from pytrends.request import TrendReq
pt = TrendReq(hl='ru-RU', tz=180)
pt.build_payload(['японский язык'], timeframe='today 12-m', geo='RU')
df = pt.interest_over_time()          # 0–100 по неделям
rq = pt.related_queries()             # top/rising
```

Пауза 8–10 с между `build_payload` — иначе 429. Сырой API трендов отдаёт 401 — только pytrends.

### Что смотреть

- Относительный интерес — только динамика и сравнение ключей между собой, НЕ абсолюты.
- related top по «японский язык» (2026-10-12): «японский язык учить» 79, **«японский язык переводчик» 52**, «перевод на японский» 44/42, «японский язык с нуля» 26. Переводческий кластер (~50) — незакрытый интент: у Origa есть OCR-перевод манги/учебников, но нет контент-страницы под «перевод японский» кластер. Кандидат в контент-план после подтверждения Wordstat-абсолютов.
- Срез трендов 2026-10-12 (12 мес, RU): «японский язык» 35–53 (без просадки, свежая точка 50), «хирагана» avg 62.8 (осенняя семестровая сезонность), «учить японский» avg 30.1.

## Аннотация про Bing (2026-10-12, после ретеста VI)

`GetKeywordStats` для RU пуст стабильно: 12 терминов × country=ru/language=ru-RU → `{"d":[]}` без ошибок. Параллельный ретест VI-коллеги на vi-VN даёт живые данные — Bing-покрытие по рынкам неровное, RU в нём отсутствует. RU-абсолюты — только Wordstat (владелец, аккаунт Яндекса). Методологическая поправка VI (бакеты Bing недельные, не дневные — месячные оценки §15.2 завышены ~6.6×) к RU не применяется: данных нет вовсе.

## Статус доступов (2026-10-16, рев. 2): OAuth жив, API-кластеры .yandex.net мертвы снаружи, рабочий путь — Yandex Cloud

Выданы владельцем: ClientID + secret (`.env` маркетинг-репо: `YANDEX_OAUTH_CLIENT_ID/SECRET`) и OAuth-токен с правами webmaster + metrica + wordstat (`YANDEX_WEBMASTER_OAUTH_TOKEN`). Токен валиден — проверен живым запросом против Метрики (HTTP 200; счётчиков Метрики не создано). Срок жизни такого токена — 6 месяцев, перевыпуск той же authorize-ссылкой.

### Диагностика API-кластеров (прогоны 2026-10-16)

- **`api.webmaster.yandex.net`** — авторитетный DNS Яндекса отдаёт 213.180.193.61, но адрес глухо чернится из Японии (KDDI, резидентный), из Railway (US) и из RU-хостинга (ВМ СПб): TCP-таймаут на 80/443, ping 100% loss. Соседние кластеры (oauth, metrika, direct) с тех же точек отвечают — кластер Вебмастера недоступен ни из-за рубежа, ни с хостинг-диапазонов.
- **`api.wordstat.yandex.net`** (легаси v1, OAuth) — DNS указывает на 213.180.204.112, который отдаёт чужой сертификат (`CN=old.wordstat.yandex.com.tr`, O=INTERSEARCH SOLUTIONS LLC): DNS-запись протухла, валидное TLS-соединение невозможно ни из одной точки.
- Паттерн общий с известной проблемой `api.music.yandex.net` (yt-dlp#15087): API-кластеры `*.yandex.net` обслуживают только RU/CIS-резидентные сети, DNS-записи местами протухли. Веб-морды (webmaster.yandex.ru, wordstat.yandex.ru) работают отовсюду — они на основном фронте Яндекса.
- Имя `webmaster.api.yandex.net` не существует (NXDOMAIN и в публичном DNS, и в DNS Яндекса) — не использовать.

### Рабочий программный путь: Wordstat v2 через Yandex Cloud

`searchapi.api.cloud.yandex.net/v2/wordstat/` — глобальный фронт Yandex Cloud, **доступен из Японии** (живой ответ валидации на пустой запрос: HTTP 400 с перечнем обязательных полей phrase/period/from_date). Авторизация `Authorization: Api-Key <ключ>` + `folderId` в теле каждого запроса. Для включения владельцу нужно (один заход, ~10 минут): консоль Yandex Cloud → биллинг-аккаунт → каталог → сервисный аккаунт → API-ключ с правом search-api.executor; ключ и folderId — в `.env` (`YC_API_KEY`, `YC_FOLDER_ID`). OAuth-альтернатива: добавить приложению скоуп `cloud:auth` и перевыпустить токен (проверено: текущий токен IAM не минтится — 401 `lacks [cloud:auth]`), но каталог и биллинг всё равно создаются руками.

### Вебмастер (поисковые запросы по сайту) — без программного пути

Данные «кто нас ставит в Яндексе» снимаются из веб-интерфейса (работает из Японии): webmaster.yandex.ru → сайт → «Поисковые запросы» → выгрузка/скриншоты владельцем → обработка скриптом (паттерн ручного ASC CSV). Программный путь откроется только с RU-резидентным эгрессом (не хостинг-диапазон).

### Wordstat через Директ — не наш путь

`api.direct.yandex.com` доступен из Японии, но метод CreateNewWordstatReport требует активного кабинета Директа с кампанией и отдельного доступа API — облако проще.

### Прочее

- Метрика: токен валиден, счётчиков нет. Кандидат — счётчик на лендинг (гео-поведение по данным Яндекса) — продуктовое изменение, отдельное решение.
- ВМ СПб (root-доступ по ключу настроен 2026-10-16) для Yandex API бесполезна — хостинг-диапазон фильтруется так же, как зарубежный. Пароль root светился в чате — рекомендована ротация (ключ уже установлен, пароль свободен к смене).

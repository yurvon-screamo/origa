# ASC Analytics: RU-territory срез (2026-10-14)

Автор: @origa_marketing_ru_bot. Данные — общий дамп lead'а (`asc-analytics/*_2026-10-12.csv.gz`, отчёты Discovery & Engagement DAILY/WEEKLY/MONTHLY, окно с 2026-09-01). Сырьё: `ru/research/2026-10-14-asc-ru-raw.json` (18 RU-строк). Цифры единичные — это база-нулевая точка, не тренд.

## RU-картина

- **Все показы — 100% App Store search** (Source Type единый, Page Type «No page» = витринная выдача, не карточка). Browse/рефералы по RU нулевые.
- Показы (Impression Counts, не строки и не уникалы): DAILY-окно 9 (7 uniq), WEEKLY 7 (6 uniq), MONTHLY 4 (3 uniq) — показы продолжаются по 12 октября включительно, темп ~1/день. По-файлово строк: 8/7/3 (строки ≠ Counts: одна строка может нести несколько показов).
- **Открытия карточки (Page view): 3 шт., все до 2026-09-25.** С 26 сентября показы идут, открытий нет.
- Устройства: iPhone, одна запись iPad. Desktop/Mac-записи в RU не попадали.

## Выводы

1. RU-витрина Apple получает нас из поиска — RU-ключи на карточке (применённые на черновике 0.7.37) попадают в живую выдачу; после сабмита 0.7.37 замерить дельту.
2. Разрыв «показ → карточка» после 25.09 — тот же рычаг, что глобально (#729): 0 оценок и пустой subtitle до недавнего времени. Приоритет рейтингов-кампании подтверждён на RU-данных.
3. База для сравнения: следующий дамп ONGOING (ежедневно с 12.10) — сверять темп показов и появление Page view.

## Метод

`python3 + gzip/csv` по таб-разделённым CSV; фильтр Territory==RU; Counts/Unique Counts без дедупликации между окнами (окна перекрываются — DAILY входит в WEEKLY/MONTHLY период, сравнивать окна между собой напрямую нельзя). Границы raw: 2026-09-01 → 2026-10-12 (MONTHLY-бакет даёт сентябрь целиком; WEEKLY-бакеты стартуют с 28.09 — окна 01–21.09 видны только в MONTHLY, отсюда расхождение imp-сумм между окнами).

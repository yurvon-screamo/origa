# Ресерч: механика «добиваний» (ghost relearning) и наш in-lesson duplicate подход

Дата: 2026-09-18. Триггер: конкурентный анализ Naminori (naminori.fun) — механика «добиваний» проваленной грамматики. Цель: понять приор-арт, научную базу, и как это соотносится с нашим текущим решением (дубли карточек внутри урока).

---

## 1. Проблема

SRS слабо справляется со «свежими» провалами: после `Again` алгоритм просто укорачивает следующий интервал, но нет ни гарантии плотной консолидации конкретного проваленного пункта, ни явного критерия «пункт добит». Крайний случай — leech-карточка: проваливается месяцами, интервалы дёргаются, конца нет.

## 2. Как устроено сейчас в Origa (код-факты)

**Дубли внутри урока** (`domain/knowledge/lesson_builder/expansion.rs`):

- Только `is_high_difficulty` карточки расширяются: `target_showings` = 2 (иначе 1). Критерий: `difficulty >= 7.0 && stability < 7.0` (`domain/memory/mod.rs`: `HIGH_DIFFICULTY_THRESHOLD`, `HIGH_DIFFICULTY_STABILITY_CAP`)
- Каждый дубль — другой `LessonCardView` (другой тип вью), показы разделены `MIN_REPEAT_SPACING = 3` карточками
- Расширение выполняется на этапе **сборки урока** (последний шаг пайплайна), по состоянию памяти ДО начала занятия

**Отбор** (`selection.rs`): high-difficulty due — первый приоритет ядра урока; padding тоже набирается из high-difficulty. Лимиты урока: 15–22 карты.

**После `Again`:** FSRS переводит карту в `Relearning` (`domain/srs.rs`), интервал короткий; карта пассивно вернётся через `is_due` в следующих уроках. `lapses` — «display heuristics only» (комментарий в `memory/mod.rs`).

**Динамика внутри урока отсутствует:** провал во время занятия не вставляет дополнительный показ. `rate_card_with_side_effects` обновляет FSRS + делает двойной рейтинг грамматической карты правила, но состав урока статичен.

**Итого текущая модель = massed practice внутри одной сессии** для карточек, уже имевших высокую сложность до урока, + пассивный пассивный возврат по due.

Замечание: факт в базе знаний `lesson-repeat-count-by-status` (3/2/1 показа по статусам) устарел — код даёт максимум 2 показа (high-difficulty), остальные 1.

## 3. Приор-арт индустрии

| Система | Механика | Ключевые параметры |
|---|---|---|
| **Bunpro** | **Ghost reviews — первоисточник концепции.** Провал грамматики = обычное ревью + отдельное ghost-ревью со СВОИМ SRS-треком | Стадии Ghost 1–4 → «Ghost Exterminated»; ghost-тайминги независимы от основного SRS |
| **bunpou.org** | Копирует Bunpro | Ghost 1–4 + «Ghost Slain» |
| **Naminori** | «Добивания»: 2×Again подряд по грамматике → призрак | Лестница 12ч → 1д → 3д; успех ≥ Good; 3 успеха = закрыт навсегда; TTL: брошен >30 суток = списан; каникулы замораживают часы; провал (Again/Hard) обнуляет счётчик; API opt-in (`ghosts: true`), undo связанный (`spawnedGhostId`) |
| **Anki** | Learning steps (дефолт 1м/10м) + Relearning steps (10м) после провала; leech | Рекомендация: шаги same-day, <1д; leech при 8 lapse → suspend, повторный флаг после 4 |
| **WaniKani** | Пассивная лестница без отдельной сущности | Провал роняет на 1–2 SRS-уровня (кап: Apprentice 1), успех +1 |

Наблюдение: Naminori почти наверняка заимствовал идею у Bunpro (терминология ghost совпадает). Bunpro — платный грамматический SRS с многолетним комьюнити; жалобы юзеров касаются объёма ghost-ревью, не самой механики.

## 4. Научная база

Механика «3 успеха по распределённой лестнице» — не эвристика, а прямая реализация **successive relearning** (Rawson, Dunlosky и коллеги, Kent State):

1. **Rawson & Dunlosky 2011** (*JEP:LMC*, «Optimizing schedules of retrieval practice»): >100 000 ответов, замеры через 1–4 месяца. Прескриптивный вывод: **начальный критерий 3 правильных воспроизведений + 3 распределённых relearning-сессии** — оптимум durability/efficiency. Именно «3 успеха» и «3 шага лестницы».
2. **Successive relearning** (Rawson, Dunlosky & Sciartelli 2013, *Educational Psychology Review*): комбинация testing effect + spacing + criterion learning. Размер эффекта реучения **d = 1.52–4.19** — очень большой.
3. **Relearning override** (Vaughn, Rawson & Dunlosky 2016): распределённое реучение доминирует над начальным критерием обучения («relearning attenuates decay» — RAD-модель). То есть *когда именно* повторять проваленное важнее, чем сколько раз в первый день.
4. **Metacognitive illusion** (Pyc & Rawson): студенты бросают практику, как только один раз вспомнили. Отсюда требование: критерий должен быть **принудительным, системным** — как раз то, что делает «3 успеха до закрытия».
5. **Spacing vs massing**: внутриурочные дубли — massed practice; она помогает краткосрочно, но долговременное удержание даёт распределение повторений **между** сессиями. Дубли и лестница — комплементарные инструменты, а не замены.

## 5. Gap-анализ: что покрываем, что нет

| Требование successive relearning | Дубли внутри урока | FSRS Relearning | Добивания |
|---|---|---|---|
| Плотное повторение сразу после провала | ⚠️ только если карта была high-difficulty ДО урока | ❌ один короткий интервал | ✅ 12ч |
| Распределённые relearning-сессии (между днями) | ❌ одна сессия | ⚠️ пассивно, интервалы плавают | ✅ 1д → 3д фиксировано |
| Критерий «закрыто» (3 успеха подряд) | ❌ | ❌ | ✅ |
| Триггер по подряд-провалам | ❌ | ❌ | ✅ 2×Again |
| Конец мучений / защита от SRS-долга | ❌ | ❌ | ✅ TTL 30 суток + терминальное состояние |
| Видимый прогресс освоения | ❌ | ❌ | ✅ счётчик успехов, «добит» |

Дыра конкретно у нас: проваленная сегодня грамматическая карта вернётся «когда-нибудь» (is_due + приоритет high-difficulty в следующем уроке), без гарантии каденции, без критерия закрытия и без UX-сигнала «пункт добит».

## 6. Направления дизайна (НЕ план реализации)

- **A. Минимальный (эволюция текущего).** Счётчик подряд-провалов (`consecutive_again`) в `MemoryHistory` для грамматических карт; при спавне условия — форсировать 2-й показ в уроке даже вне high-difficulty + повышать приоритет отбора несколько занятий. Не даёт междневной лестницы и критерия закрытия.
- **B. Ghost-стейт (в духе Naminori/Bunpro).** Отдельный value object рядом с `MemoryState` (не трогая планировщик): `{ successes, due_at, resolved_at }`, лестница 12ч/1д/3д, списание по TTL. В `lesson_builder` — отдельная «рука добиваний» с высшим приоритетом; в UI — прогресс добивания и момент «добит».
- **C. Bunpro-style отдельный SRS-трек** — самый тяжёлый, избыточен для нашей архитектуры.

Открытые вопросы: только грамматика или все `RateMode`? Взаимодействие с режимом знакомства (карта до первого ревью)? Офлайн-мерж: счётчики сейчас merge по `max()` — подряд-счётчик при дивергенции неточен (приемлемо ли?). Упирается ли лестница в lesson-based flow (урок собирается заранее)?

## 7. Риски

- Статическая сборка урока vs same-day добивание: нужна либо динамическая вставка, либо рука добиваний на следующем уроке (каденция 12ч в lesson-модели достигается только если юзер открывает урок вечером)
- Двойной рейтинг грамматики уже существует (`handle_grammar_dual_rating`) — спавн/учёт добиваний не должен задваиваться с ним
- Офлайн-мерж `max()` ограничивает точность подряд-счётчиков
- Объём: Bunpro-юзеры жалуются на завалы ghost-ревью — нужны дневные лимиты добиваний

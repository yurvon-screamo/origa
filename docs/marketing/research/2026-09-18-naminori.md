## 2. Страница грамматики как продуктовая единица (анализ `/grammar/te-imasu`)

Структура страницы — лучшая из виденных в русскоязычном сегменте:

1. **Шапка**: уровень, регистр (Нейтральная/Разговорная/Формальная/Письменная)
2. **Структура**: формулы конструкции (тэ-форма + います / + いません) с мини-примерами
3. **Подробно**: употребления по смыслу (3 шт.), разговорные стяжения (ています→てます), связанные паттерны (まだ〜ていません)
4. **Нюансы**: gotcha-ловушки (知っています→知りません; глаголы мгновенного перехода = состояние-результат)
5. **30 примеров**, каждый: фуригана инлайн + перевод + **семантический тег** («действие прямо сейчас» / «состояние-результат» / «регулярное занятие»); progressive disclosure (первые 5, «показать остальные 25»)
6. **Примеры сообщества**: UGC с дисклеймером о немодерации + механизм жалоб
7. **Похожие конструкции — в чём разница**: связанные пункты с **дифференцирующей пометкой** (ます — привычка/будущее, ています — процесс/состояние)
8. **Сравнить с похожими**: интерактивный AI-разбор разницы с выбранной конструкцией
9. **Фуригана-режимы**: Всегда / При наведении / Скрыть (a11y + progressive difficulty)
10. **Следующая конструкция** — методический порядок как навигация (куррикулум)

## 3. API-поверхность: инженерные паттерны

**Полный список эндпоинтов**: me, overview, stats, stats/today, due, queue, review, review/batch, review/undo, learn-new, cards (GET/POST), vocab/decks (CRUD + cards + bulk), vocab/cards (move/forget/delete/update/suspend/setSuspended/bury/scene), lookup, dict, audio, translate, grammar (каталог/slug/lookup/check), decks (публичные), dicts/naminori-ru (+meta), dicts/naminori-grammar, media/store, media/animate, media/{file}, extension/version.

**Заслуживающие внимания паттерны:**

1. **`POST /api/v1/grammar/check` — проверка ответа как сервис**: ромадзи→кана, кандзи↔кана, эквивалентные формы, вежливость. Логика приёма ответа живёт НА СЕРВЕРЕ и не дублируется в 6 клиентах. Третья сторона пишет клиент и не переписывает «выверенную логику»
2. **`GET /api/v1/grammar/lookup` — обратный поиск**: живая фраза 食べてもいいですか находит пункт 〜てもいい («вхождение наоборот», ILIKE так не умеет). Нормализация: тильда-заполнители, многоточия, полноширинные пробелы
3. **Offline-first first-class**: cursor-пагинация стабильной выдачи (`order=stable`), batch до 500 с дедупом по (вид, карточка, reviewedAt), undo-токены, явная семантика duplicate/not_found
4. **Словари как дистрибуция**: Yomitan v3 zip-пакеты на каждый словарь; freshness по **раскладу** (хешу состава), не по числу статей — с честной заметкой об инциденте 23.08.2026, когда словарь пропал, а число термов осталось прежним
5. **`context=1` — «режим в предложении»**: к каждой карточке очереди прикладывается живая фраза из корпуса, подобранная так, чтобы **незнакомых слов в ней было минимум**. Настройка аккаунта, не клиента
6. **`POST /api/media/animate`**: анимированный AVIF из 2–24 кадров — 2 секунды сцены ~12 КБ, **дешевле статичного скриншота**; оправдание: браузер не умеет кодировать анимированный AVIF
7. **CORS-исключение с обоснованием**: у media-ручки нет CORS, но поддержан Range — «без этого `<audio>` в iOS Safari не проигрывает»
8. **Device-code auth** (NMN-XXXX): один паттерн для очков (не печатают), бота, десктопа — «вход одной кнопкой» везде
9. Rate-limits per-user по типам операций (чтение 240/мин, batch 60/мин), ошибки с машинным кодом + готовой русской фразой + details по полям
10. **Документация как продукт**: каждый параметр объясняет ЗАЧЕМ (почему offset нет у очереди, почему дедуп-ключ включает вид, почему aiKey едет в /me — «десятки попапов ради одного бита»)

## 5. Идеи для Origa (по value/effort, из функционального анализа)

1. **Обратный grammar-lookup** (фраза → конструкция) в наш grammar-модуль — у нас уже есть токенизация lindera, которой у них нет; совпадение поверхностей «конструкция в предложении» — естественное расширение quiz-генерации
2. **Единая проверка ответа** как доменная функция (у нас уже есть `domain/grammar/` quiz generation — довести до «эквивалентность форм + вежливость + ромадзи-ввод» одной точкой входа)
3. **Cram-режим** — дёшево поверх нашей lesson-модели (отбор без учёта due, все проваленные/lapse)
4. **«Режим в предложении»**: подбор примера-контекста с минимумом незнакомых слов — у нас есть частотность и knowledge_set, чтобы считать «знакомость»
5. **Пробники JLPT с таймером** — контент + одна сессия-модификатор урока
6. **SEO-урок Naminori**: 556 публичных страниц грамматики = programmatic SEO лейка. У нас контент только в приложении; лендинг мог бы публиковать публичный срез грамматики (в духе наших /docs)
7. **Yomitan-совместимость экспорта** — дёшево, открывает юзера-экосистему
8. Дального горизонта (нужен серверный слой поверх синка): community decks, UGC-примеры, лидерборд, публичный API

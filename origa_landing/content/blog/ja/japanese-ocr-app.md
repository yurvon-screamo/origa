# 日本語OCRアプリ：得意なことと弱点

辞書に日本語を入力するのは苦痛です。漢字の読みを知らない場合、部首で調べる必要があります: 画数を数え、部首を特定し、表を渡り歩く。1単語を見つけるのに60秒の操作です。スマホではさらに悪くなります。これがOCRが解決する問題です: テキストを撮影すれば、読みと意味が数秒で得られます。

しかし「日本語OCRアプリ」は曖昧な検索で、それで出てくるほとんどのアプリは、より長い問題の前半しか解決していません。読みをくれます。覚える助けにはなりません。これは、異なるタイプのOCRアプリが実際に得意なこと、それぞれの弱点、そして1つの看板を解読するだけでなく日本語を学びたい場合に注目すべき点のガイドです。

Origaを含みます — 限界も率直に挙げます。

## 日本語OCRが実際に解決すること

実際のユースケースは3つあり、それぞれ違う方向を向いています:

1. **翻訳ルックアップ。** レストランにいて、メニューが漢字だらけ、料理の中身を知る必要がある。速いOCR + 信頼できる翻訳が欲しい。学習は気にしません。
2. **読解サポート。** 漫画、教科書、ニュース記事を読んでいます。セリフやコマをOCRし、未知の単語の読みを得て、読み続けたい。学習中ですが、OCRはルックアップツールです。
3. **語彙マイニング。** OCRしたすべての単語が、後で復習するフラッシュカードになってほしい。OCRは一発ルックアップではなく、SRSへのパイプラインです。

ほとんどのアプリはユースケース1のために作られています。2を扱うのは少数です。3を大幅な手作業なしで扱うのはほぼありません。どれが必要かを知ることが、「最高」のアプリを決めます。3つすべてに勝つアプリはありません。

## 3つのカテゴリ

### 汎用OCR（Google レンズ、Apple Live Text、Microsoft Edge モバイル）

**強み:** 印刷テキストでの高精度。現代のiOSのLive Textは、日本語をスクリーンショットとほぼ同等の精度で写真から認識します。Google レンズはOCRの上に翻訳を重ねるので、1文字も読めなくても意味が得られます。

**弱み:** 学習のための行き止まりです。認識結果はプレーンテキスト: ふりがななし、辞書やSRSとの統合なし、スキャンしたものをフラッシュカードとして記録する方法なし。翻訳を1回読んで単語を忘れます。日本語を**学びたい**なら、レンズはルックアップツールであって学習ツールではありません。

**ユースケース:** 旅行、メニュー、看板、荷物。ユースケース1。

### OCR内蔵の辞書アプリ（Imiwa、Nihongo、KanjiSnap）

**強み:** OCR結果が直接辞書検索に流れ込むので、読み・意味・活用・例文が得られます。Imiwa（iOS/Android）はOCRを何年も前から持ち、Nihongo（iOS/Android）はPro機能として搭載し、KanjiSnap（iOS）はAppleのLive Textに依存しています。多くのアプリは単語をスター登録して後で見る機能があり、語彙キャプチャの緩い版です。

**弱み:** OCR機能自体がしばしば二級市民です。認識品質は、特に装飾フォントや手書きテキストで変動します。「スター」リストは間隔反復システムではありません。スター付き単語を500個溜めて、一度も復習しないことになります。OCRは記憶のあるルックアップツールであって、学習ツールではありません。注意: 人気の辞書の一部（AndroidのAkebi、iOS/AndroidのShirabe Jisho）は内蔵OCRをまったく持っていません。優秀なルックアップツールですが、単語は自分でタイプまたはペーストします。

**ユースケース:** 読解サポート、中級レベルのルックアップ。ユースケース2。

### 漫画特化OCRツール（manga-ocrモデル、Poricom、YomiNinja、ブラウザ拡張）

**強み:** 漫画という特定の問題に調整されています。オープンソースの`manga-ocr`モデルは、縦書き、複数行の吹き出し、装飾フォントを汎用エンジンよりうまく処理します。デスクトップラッパー（Poricom、YomiNinja）とブラウザ拡張（Chrome用Manga OCR、Namida-OCR）は、認識を読書フローに統合します: コマを選択し、テキストを得る。

同じ問題への別ルートが**mokuro**です: コマを1つずつ認識する代わりに、漫画の巻全体を前処理して、テキストが選択可能・ホバー可能なHTMLページにします。結果をブラウザで、Yomitanにポップアップ辞書の仕事をさせて読みます。アプリではなくバッチパイプライン — セットアップは面倒ですが、マイニングには強力です。**Yomu**は逆のアプローチを取ります: OCRとルックアップを内蔵したiOS読書アプリで、ツールチェーンを組み立てずに漫画や紙のページを読むことを狙います。

**弱み:** 狭いです。教科書のスキャンや現実世界のテキストの写真には使えず、漫画用です。そして同じ保持のギャップが適用されます: Yomitan + AnkiConnect経由でAnkiにパイプしない限り、OCRはルックアップを供給するものであってSRSではありません。漫画マイニングのパワーユーザーは典型的にその3アプリスタックを実行します。そのようなパイプラインが実際の学習にどう収まるかは、[漫画学習ガイド](/ja/blog/learn-japanese-from-manga)を参照してください。

**ユースケース:** マルチツールパイプラインの設定を厭わない学習者のための漫画読解サポート。ユースケース2。

### 学習統合OCR（Origaの位置）

Origaはユースケース3のために作られています: 語彙マイニングです。OCRはカード作成パイプラインの入口です: 写真をスキャン、スクリーンショットを貼り付け、教科書のページを撮影する。OCRはローカルで動作し（端末上のNDLOCR-Lite、アップロードなし）、単語を抽出し、それぞれが読み・翻訳・音声・出現した文付きのフラッシュカードになります（[OrigaがOCR・ふりがな・語彙連携をどう扱うか](/ja/docs/capture)を参照）。

トレードオフは明示的です: Origaは翻訳ツールでも辞書ルックアップアプリでもありません。看板を1回読めればいいだけなら、Google レンズの方が速いです。Origaは、その単語を二度と調べなくて済むことを目的とする学習者のためにあります。

## ツール一覧

これらすべてを分けるチェックリストの問いは「OCR結果はどこへ行くか」です。1つの表にまとめます:

| ツール | カテゴリ | OCR結果の行き先 |
| --- | --- | --- |
| Google レンズ | 汎用 | 翻訳オーバーレイ — 1回読んで、何も残らない |
| Apple Live Text | 汎用 | 選択可能テキスト — 自分で別アプリに運ぶ |
| Imiwa、Nihongo | 辞書 + OCR | 辞書エントリー; せいぜいスター単語リスト |
| KanjiSnap | 辞書 + OCR | 辞書エントリー（Live Text経由の認識） |
| manga-ocr（モデル） | 漫画特化 | 認識テキスト、ルックアップとマイニングパイプライン用 |
| Poricom、YomiNinja | 漫画特化（デスクトップ） | コマテキスト → 読みながらルックアップ |

## 日本語OCRアプリで見るべきこと

カテゴリを実際に分けるチェックリスト:

- **OCR結果はどこへ行くか？** プレーンテキストだけ = 翻訳ツール。辞書エントリー = ルックアップツール。フラッシュカードパイプライン = 学習ツール。最初の2つは何の保持も助けません。
- **端末上かクラウドか？** クラウドOCRはしばしばより正確ですが、インターネット接続が必要で、写真をサーバーに送ります。端末上OCR（NDLOCR、Apple Vision framework、端末上MLモデル）はオフラインで動き、プライベートです。どちらかが普遍的に優れているわけではありません。オフライン + プライバシーが必要か、最大精度が必要かで選んでください。
- **縦書きを処理するか？** 日本語はしばしば縦に組まれます — 特に漫画と小説で。多くの汎用OCRエンジンは横書きに調整されており、縦の入力を崩します。
- **ふりがなを処理するか？** ふりがなは漢字の横に印刷された小さなかなです。安いOCRはそれを別の単語として読み、出力を汚染します。良いOCRはふりがなを無視するか、正しい漢字と関連付けます。
- **OCRはパイプラインの終わりか、始まりか？** これがほとんどの「最高のOCRアプリ」リストが飛ばす問いです。答えが「終わり」ならルックアップツール、「始まり」なら学習ツールです。

## Origaの取り組み方

具体的に、それらの軸のどこにOrigaが位置するか:

- **パイプライン:** OCR → 単語抽出 → 文 + 読み + 翻訳 + 音声付きフラッシュカード → FSRSスケジュールの復習。スキャンした各単語が、再び見ることになるカードになります。
- **端末上。** NDLOCR-Liteがローカルで動きます。機内モードでスキャン可能です。何も端末を離れません。
- **縦書き:** 対応。
- **ふりがな処理:** Origaは抽出した漢字に自前のふりがなを生成し、学習済みの漢字ではそれを隠します。システムが自前のふりがなを生成するため、OCRは印刷されたふりがなの曖昧性解消をする必要がありません。
- **辞書統合。** OCR結果は直接二言語辞書に入ります — 別のアプリへのコピーペーストはありません。

要点: Origaは、レンズ、辞書アプリ、Ankiを3つの別ツールとして持つことに疲れた学習者のためのOCRアプリであって、OCRが実際に学習パイプラインに供給されることを望む人のものです。

## 既知の限界

- **Origaは翻訳アプリではありません。** 看板を1回読む必要があるなら、Google レンズを使ってください。Origaのパイプラインは一発ルックアップには過剰です。
- **装飾フォントでのOCRは完璧ではありません。** 手描きの漫画の文字、装飾フォント、一部の擬音語は誤読されます。手動修正を予算に入れてください。
- **漫画リーダーではありません。** コマはスキャンできますが、Origaは漫画自体を表示しません。お好みのリーダーと組み合わせてください。
- **今日時点でYomitan統合はなし。** ワークフローがYomitan → Ankiなら、Origaはまだそのパイプラインに直接組み込めません。既存のAnkiデッキのインポートは可能ですが、ライブパイプはそこにはありません。
- **モバイルOCR品質はカメラと照明次第です。** すべてのスマホOCRアプリと同じです。鮮明な写真、均一な光、傾きなし。いつものルールが適用されます。

## 選び方

スマホには、ほぼ確実に汎用OCRアプリが既にあります（iOSのLive Text、Androidのレンズ）。ほとんどの一発翻訳にはそれで十分で、無料です。問いは、「1回翻訳」を卒業して「キャプチャして学ぶ」が必要かどうかです。必要になっているのは: 同じ漢字を見続けて覚えていない場合、辞書アプリで単語をスターして一度も復習しなかった場合、漫画の読書が次の章までに忘れる単語を生産している場合です。その場合、学習統合OCRが欠けているピースです。パイプラインを端から端まで試すには[Origaをダウンロード](/download)してください。

## FAQ

### 日本語OCRは信頼できる精度ですか？

きれいな印刷の横書きテキストでは、現代のOCR（Apple Live Text、Google レンズ、NDLOCR）は日常のルックアップに十分信頼できます。縦の漫画テキストと装飾フォントでは、より多くのエラーを想定し、手動修正を予算に入れてください。ベンダー公表の精度数字はまれで、常に特定のテストセットに紐付くため、マーケティング文で読む丸いパーセンテージを信頼しないでください。手書き・装飾テキストは全体的にまだ信頼できません。

### OCRはオフラインで動きますか？

アプリによります。クラウドベースのOCR（ほとんどの翻訳アプリ）にはインターネットが必要です。端末上OCR（OrigaのNDLOCR-Lite、Apple Live Text）はオフラインで動きます。電車や飛行機で学ぶなら、端末上が重要です。

### 漫画をフラッシュカードにOCRできますか？

はい、ただしOCRをSRSに接続するパイプラインが必要です。Origaはこれを端から端まで行います。代替はYomitan → Ankiで、より設定可能ですがセットアップが必要です。

### なぜただGoogle レンズを使わないのですか？

レンズは一発翻訳に優れています。学習ツールではありません。OCR結果は、間隔反復への道のないプレーンテキストです。スキャンしたものを覚えたいなら、別のカテゴリのアプリが必要です。

### OrigaのOCRは写真をサーバーに送りますか？

いいえ。NDLOCR-Liteは端末上で動きます。スキャンがスマホやコンピュータを離れることはありません。
